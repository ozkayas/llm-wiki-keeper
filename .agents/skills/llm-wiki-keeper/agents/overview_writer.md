# Agent — overview_writer

**Purpose.** Rewrite `wiki/overview.md`: the one page a newcomer reads first.
Navigation and orientation, not argument.

**Model.** Run on a Sonnet-class model (Claude Sonnet, or the equivalent mid-tier
model of your provider). If unavailable, use the harness default.

Read `.agents/skills/llm-wiki-keeper/PAGES.md` and `.agents/skills/llm-wiki-keeper/CONVENTIONS.md`
before writing. If that path does not exist, look in the directory of this skill file.

**Clock.** Never type a timestamp. Run `date -u +%Y-%m-%dT%H:%M:%SZ` once, when you
write the page, and use the output for `generated.at` (and `created` on a new page).
You receive no `now` input.

## Inputs

| Input | Meaning |
|---|---|
| `wiki_dir` | Path to `wiki-<slug>/`. |
| `existing_page_path` | The current overview, or `null` — read it to preserve `created`. |
| `output_path` | `wiki-<slug>/wiki/overview.md`. |
| `mentions_json` | The `count_mentions.py` output, so you can name the slugs sitting at one mention without recomputing them. Given inline, or as a path to a file containing the script's JSON; when given a path, read the file. |
| `language` | Page language, from `config.yml` (e.g. `en`). Write all prose in it. Slugs, keys and code stay as specified. |
| `tags` | `optional` or `forbidden`, from `config.yml`. You **never invent tags**, in either mode. `optional`: keep any `tags:` already on an existing page when rewriting. `forbidden`: write none and drop any present. |

## Process

1. **Walk frontmatter, do not read pages.** This is the context-discipline rule
   that makes the overview cheap on a wiki of any size:

   ```bash
   for f in <wiki_dir>/wiki/sources/*.md <wiki_dir>/wiki/entities/*.md \
            <wiki_dir>/wiki/concepts/*.md <wiki_dir>/wiki/repos/*/*.md; do
     awk '/^---$/{c++; next} c==1' "$f"; echo "---END---"
   done
   ```

   `title`, `description`, the `sources` list, `entities:` / `concepts:` and
   `source_count` are enough to see the shape of the wiki.
2. **Read at most 5 full pages**, and only ones you are about to characterize.
   If you want a sixth, stop: write what you can support and say the rest is
   thinner than it looks.
3. **Find themes from co-citation** — which pages get cited by the same sources.
   Themes are observed, not invented; 2–4 of them, each naming its pages and its
   strongest source.
4. Write `output_path` per `.agents/skills/llm-wiki-keeper/PAGES.md § overview`: `type: overview`, `title`,
   one-sentence `description`, `created`,
   `generated: { by: llm-wiki-keeper/overview_writer, at: <output of `date -u +%Y-%m-%dT%H:%M:%SZ`> }`, `sources`
   (only the pages your theme paragraphs actually cite, with `resource` relative to
   `wiki/`, e.g. `sources/<slug>.md`), `total_sources`. Do not write `total_pages`; it is derived data. Theme
   paragraphs cite with footnotes `[^id]` keyed to `sources[].id`; links are
   standard relative markdown links from `wiki/` (`concepts/mcp.md`, no `../`),
   never `[[wikilinks]]`. Include the Repos section when `wiki/repos/` exists.
   The "waiting at 1 mention" slugs you list must each be **linked**
   (`[slug](concepts/slug.md)`, promissory links are fine) so they show as hollow
   graph nodes.
   Never write `verified`, `timestamp` or `stale_after`.
5. Return the receipt:

```json
{"page": "wiki/overview.md", "total_sources": 12, "themes": 4, "full_reads": 3}
```

## Guardrails

- **Synthesis is separate.** Theme paragraphs carry only sourced statements, with
  footnotes. Any interpretation, comparison, evaluation or inference goes on its own
  `> Synthesis:` line. Bad: "Both notes agree the harness is the real bottleneck.[^a][^b]"
  (neither says that). Good: "One note covers loop exits.[^a] The other covers tool
  declaration.[^b]" then "> Synthesis: Both put control in the harness."
- **A footnote supports only what its source states.** A claim combining two
  sources needs both footnotes; never attribute a detail to a source that does not
  mention it.
- **Preserve `created`** and unknown frontmatter keys; bump `generated.at`.
- **Never invent a theme to look organized.** If the sources do not cluster, say
  the wiki is still a list and show the list.
- **The "waiting at 1 mention" line is not filler** — it is the wiki's to-do list,
  and it is the most useful line on the page for deciding what to ingest next.
- **One file.** The index is generated by a script; do not hand-write navigation
  that `build_index_md.py` already produces.
